# 麦麦积分精算师 · MCD Points Actuary

> 麦当劳会员积分是**会过期、有多种花法、且选错就差 13 倍**的资产。
> 本项目把「兑换 / 抽奖 / 过期」三条路径折算到同一把尺子上 —— `元/积分`，给出可复算的结论。

## 一句话价值

同样 800 积分，在**真实积分商城**里有两种花法：

| 兑换标的 | 所需积分 | 换回价值 | 每积分价值 |
|---|---|---|---|
| `21.9元巨无霸可乐组合` | 800 | ¥21.90 | **0.0274 元/积分** |
| `18.8元麦辣鸡腿汉堡两件套` | 50 | ¥18.80 | **0.3760 元/积分** |

**差 13.7 倍。** 而这类"积分黑洞"在商城里不止一个 —— 它们往往面值看着最大（21.9 元、800 积分），
却是效率最低的选项。本项目做的就是把它们全部算出来、标出来、给出替代方案。

## 项目介绍

麦当劳优惠体系里，**钱**已经有很多工具在算，但**积分**几乎没人算。积分有三个特殊性，
使它天然是一个数学问题而非经验问题：

1. **会过期** —— `query-my-account` 直接返回「本月将过期 / 下月将过期」积分；
2. **多条消耗路径** —— 兑换（确定收益）、抽奖（概率收益）、过期（收益归零）；
3. **同积分价值差极大** —— 商城标的的 `元/积分` 跨度可达一个数量级。

**两阶段求解**

| 阶段 | 做什么 | 在哪运行 | 为什么 |
|---|---|---|---|
| Stage 1 · 本地建模 | 从标的名称解析面值、算全量价值矩阵、识别陷阱 | **本地**，零网络 | 限流 600 次/分钟，不可能逐项试探 |
| Stage 2 · MCP 取真值 | 账户 / 商城 / 抽奖 / 菜单原价（**各一次**） | 麦当劳 MCP | 拿到真实积分、真实奖池、真实原价 |

**四个引擎**

| 引擎 | 回答的问题 | 数学内核 |
|---|---|---|
| 价值矩阵 | 同样的积分，换什么最值？ | `ypp = 面值 / 积分`，中位数识别陷阱 |
| 抽奖期望 | 积分该换券还是抽奖？ | **零概率信息下的分层夹逼**（见下） |
| 背包组合 | 我攒了 N 积分，怎么花？ | 带件数上限的二维 0/1 背包 DP |
| 到期止损 | 积分快过期了怎么办？ | 面值最大化 + 抽奖兜底 + 损失量化 |

### 亮点：MCP 不返回中奖概率，怎么判断抽奖划不划算？

`query-lottery-info` 只给奖品名称，**不给概率**。常规做法只能"猜"，本项目改用**分层夹逼**，
让每个结论都带上它的成立条件：

| 判定 | 成立条件 | 含义 |
|---|---|---|
| `dominated` | `奖池最高单项 < 打平线` | **必亏**，不需要任何概率假设 |
| `robust` | 假设「永不上头奖、其余等概率」仍划算 | 结论**不依赖**头奖命中率 |
| `likely` | 全奖池等概率期望达标 | 倾向抽，但依赖头奖命中率 |
| `depends` | 仅当头奖命中率 ≥ p 才划算 | **反解出一元不等式**给出精确门槛 |

其中"打平线"= 单次消耗积分 × 兑换基准 `ypp` —— 即**这些积分如果拿去兑换能保证拿到的价值**。

## 核心特性

- 🎯 **统一标尺**：兑换 / 抽奖 / 过期三条路径全部折算为 `元/积分`，可直接比较
- 🕳️ **积分黑洞预警**：给出每个低效标的的**机会成本金额**（如"800 积分换 21.9 元，机会成本 ¥88.50"）
- 🎲 **抽奖期望值边界分析**：在零概率信息下给出可复核的结论与概率门槛
- ⏳ **到期止损**：把"还有多少积分会白扔"变成一个带金额的结论
- 📅 **上架周期校验**：识别 `downTime` 与 `status` 冲突的标的并标为"待复核"
- 🧮 **金额全程以「分」整数计算**，无浮点误差
- 🔌 **离线可测**：60 项单元测试全绿，无需 Token
- 🚦 **限流友好**：全流程 MCP 调用次数为**个位数**

## 目标用户

| 人群 | 痛点 | 本 Skill 的价值 |
|---|---|---|
| 麦麦会员 / 常客 | 积分躺在账户里，不知道换什么 | 直接给"换哪件最值 + 清单" |
| 收到"积分将过期"提醒的人 | 知道要过期，不知道该换什么止损 | 最快的消耗路径 + 剩余损失金额 |
| 爱抽奖的用户 | 不知道抽奖是不是在烧积分 | 给出抽与不抽的判定条件 |
| 薅羊毛 / 精算型用户 | 想系统性地知道商城的价值结构 | 全量价值矩阵 + 黑洞清单 |

## 安装方法

### 1. 申请麦当劳 MCP Token

访问 <https://open.mcd.cn/mcp> → 右上角「登录」（手机号验证）→「控制台」→「激活」→ 复制 Token。

### 2. 配置 MCP 连接器

将 `mcp-config.example.json` 中的 `${MCD_MCP_TOKEN}` 替换为实际 Token，填入你的 MCP Client（WorkBuddy / Cursor / Cherry Studio / Trae 等）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer YOUR_MCP_TOKEN" }
    }
  }
}
```

### 3. 设置环境变量（脚本层需要）

```bash
export MCD_MCP_TOKEN=你的Token        # Linux / macOS / Git Bash
setx MCD_MCP_TOKEN 你的Token          # Windows（需重开终端）
```

### 4. 运行

```bash
git clone https://github.com/akexin/mcd-points-actuary.git
cd mcd-points-actuary
python -m unittest discover -s tests        # 60 项离线自检
```

> 无需 `pip install`：本项目只依赖 Python 标准库。

## 能力演进

本项目不是一次性产物，而是**两轮迭代**的结果 —— 仓库同时保留两层能力：

| 版本 | 命题 | 引擎 | 状态 |
|---|---|---|---|
| **v1** | 怎么**买**最省？（组合剪枝 + MCP 精算） | `optimize_deals.py` | 已完成，13 项测试 |
| **v2** | 怎么**花积分**最值？（价值矩阵 + 期望值边界） | `points_engine.py` | 当前主线，47 项测试 |

> 为什么转向？v1 把"钱"算到了极致，但发现**钱之外的资产没人算** —— 积分同样是真金白银，
> 却有"会过期、多路径、价值差 13 倍"三个特性，是更适合建模的对象。

## 数据说明

`data/` 下的商城标的、奖品池与金额均来自**真实 MCP 响应的脱敏快照**（不含账号、Token 等隐私字段），
用于离线复现与文档演示。**商城的下架/上新会改变结果**，请以实时 MCP 返回为准。
